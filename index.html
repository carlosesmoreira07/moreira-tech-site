Trajetória

De executar testes a arquitetar qualidade.

Início

Qualidade invisível, risco silencioso

Testes manuais tardios, sem foco em risco. Bugs descobertos na véspera do release. Automação como checklist — não como estratégia.

Evolução

Engenharia, não execução

Arquitetura de suítes orientadas a risco. Playwright e k6 integrados ao CI/CD. Quality Gates bloqueando releases com evidências auditáveis.

  • Risk-based testing
  • CI/CD com bloqueio automático
  • Performance & Security como qualidade
  • IA assistiva — decisão humana
Propósito

Qualidade como disciplina estratégica

A Moreira Tech aplica Quality Engineering para que decisões de release sejam feitas com base em evidências — não em intuição.

"IA acelera a análise. Engenharia decide."

Sistema de Qualidade

Risco → Controle → Evidência → Decisão.

Cada teste cobre um risco real. Cada execução gera evidência auditável. A decisão de release é sempre humana.

01

Risk-Based Quality

Jornadas críticas determinam onde testar, com qual profundidade e qual threshold é aceitável.

02

Quality Gates em CI/CD

Playwright Web & API bloqueando Pull Requests. Falha silenciosa não existe no pipeline.

03

Performance & Security

k6 com thresholds p95 e verificação de autorização HTTP 401 como parte do gate, não como etapa separada.

04

IA Assistiva

IA correlaciona demanda, risco e cobertura. A aprovação de release é sempre revisão humana — nunca automática.

Quality Engineering Lab

Sistema de referência que demonstra, na prática, como estratégia de risco, automação cross-domain Playwright, Quality Gates e evidências auditáveis funcionam juntos em um produto real.

Risco
Alteração de preço no Admin não se propagar corretamente ao carrinho da Storefront.
Controle
Playwright valida a propagação end-to-end Admin → Storefront a cada Pull Request.
Gate
PR bloqueado automaticamente se houver divergência de valor financeiro.
